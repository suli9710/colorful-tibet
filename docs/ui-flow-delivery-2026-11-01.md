# 七彩西藏 UI 与操作流程改进

日期：2026-11-01。分支：`codex/travel-ui-flow`。实现交付时未推送、合并或部署；后续经用户授权推送独立分支，未合并或部署。保留开始任务时已有的工作区改动。

## 范围与方法

阅读 README、AGENTS、路由、规划页、首页、公共导航、草稿和认证实现后，启动本项目 Vite 开发服务并实际查看页面。5173 最初被另一项目占用，本项目使用 `http://127.0.0.1:5174`；生产构建预览使用 4174。截图中的修改前是任务开始时的工作区，而非 Git HEAD。

核心用户是准备赴藏的自由行旅客，主要任务为了解目的地、选旅行节奏、生成建议、逐日阅读和记录调整、核对费用与出行条件、保存或携带行程。本轮实施首页入口、规划核心流程和跨页面公共视觉；酒店、景点、社区等页面继承公共样式，未逐页重构业务表单，后台未作设计改造。

## 优先解决的五个问题

| 优先级 | 修改前 | 本轮实现 |
| --- | --- | --- |
| P1 | 首页主动作是探索景点，规划以“AI”技术名作为入口 | 首页首要动作“规划我的行程”，导航统一任务名；景点和热图入口保留 |
| P1 | 规划页装饰和纵向选项挤占空间，手机生成入口很深 | 紧凑的双列偏好、有效空态、固定生成入口；已有结果仍可套用预设 |
| P1 | 正文、每日安排、预算、保存分散 | “选择偏好 → 逐日调整 → 核对与保存”锚点；逐日展开、原安排跳转、参考预算摘要 |
| P1 | 分享比保存突出，重新生成直接替换，重试范围过大 | 明确保存/导出主操作；替换确认；报价/旅行包单独重试；清空备注确认与撤销 |
| P1 | 未知费用显示零；时间被包装成进度；预算与可订状态易混淆 | 缺失费用“待获取”；不确定进度仅显示等待状态/已等待时间；参考费用、人数、库存与实际预订边界就近说明 |

## 关键流程与行为

- 首页直接进入规划；预算、天数、兴趣仍使用既有接口。西藏为既定目的地，地区由系统推荐，没有新增无接口支撑的目的地筛选。
- 偏好继续按原安全机制在浏览会话内保存；生成正文和私密备注不新增浏览器持久化。备注仅在本页内存保留，站内往返由 KeepAlive 保持；刷新/关闭尝试提示先导出，浏览器最终允许离开后备注会丢失。
- 每日“调整”是用户备注，不是修改原行程条目或订单。导出的 Markdown 附带备注及参考性质说明；云端保存仍只收藏原行程，分享仍为原生成内容。没有伪造逐日服务端编辑能力。
- 清空单日备注有确认及撤销；重新生成有替换确认。生成、保存和明细操作有重复请求防护。修改下一次偏好不会篡改当前结果参数、每日列表、分享和导出名称。
- 重试已有结构行程只重新读取它的报价与旅行包；旧请求晚到不会覆盖新行程。旅行包失败有明确重试入口。
- AI 文本原有 30 天上限保留；结构明细实际接口只支持 15 天，16–30 天明确说明仅文字能力，不再发送必然失败的结构请求。
- 保留认证、CSRF、权限、外部预订校验、Markdown 清洗和既有业务接口；未改后端业务逻辑、依赖版本或部署配置。

## 视觉体系

暖纸色 `#F7F3EE`、实色面板 `#FFFDF9`、藏红 `#8B2E3A`、深正文 `#1A1520`、次级文字 `#69594C`、焦点蓝 `#2D5F8A`。保留中文衬线标题与经幡细线；减弱云纹、玻璃和重复角饰。统一控制圆角、面板圆角、轻阴影、44px主要触控目标和可见键盘焦点。未引入额外字体或组件库。

## 未验证与后续事项

1. 本机 Docker 未运行，MySQL 服务停止且启动被系统拒绝；因此没有完成真实数据库下的登录、AI/备用生成、收藏持久化、报价、库存或外部交易联调。测试响应只验证前端行为。不得把此轮交付当成生产发布批准。
2. 新增文案目前中文，藏文使用中文回退；原藏文切换及持久化通过回归。新增旅行、安全提示应经人工藏文审校后补齐。
3. 真正逐日修改/排序并保存到服务端、可选出行人数/日期/地区，需要后续业务设计与接口支持。本轮没有把本地备注冒充已完成这些功能。
4. 实际浏览器200%缩放、真实手机软键盘、屏幕阅读器、藏文管理员完整导航，以及所有业务页的状态矩阵尚未全面验证。已覆盖的视口与内容放大测试不能替代这些检查。
5. 项目没有现成的页面性能数值门禁；当前只记录构建产物与本机样本，后续需在固定环境建立可比基线和预算。

继续开发请使用5174的开发服务；4174仅供本轮生产构建验证。未启动真实业务后台。后续 GitHub 推送仅包含本轮 UI 改动；之前未提交的后端、部署、安全、轮播暂停和外链跳转修复继续保留本地。
