要在项目中实时区分人类用户和 AI/自动化操作，不能只靠单一手段。现代 AI 代理（尤其是基于视觉语言模型的浏览器代理）和高级脚本能够模拟人类行为，因此你需要一个**多层实时检测体系**，从客户端特征、交互生物特征、行为序列和服务端风控几个维度联合判断。

---

## 一、实时监督的核心架构

```
用户浏览器/客户端
  │
  ├─ 行为采集 SDK (JS/iOS/Android)
  │    采集：鼠标轨迹、触摸、键盘、滚动、设备指纹、事件时间戳等
  │
  └─ 实时数据通道 (WebSocket / 高频上报)
        │
        ▼
   消息队列 (Kafka / Pulsar)
        │
        ▼
   实时计算引擎 (Flink / 规则引擎 + 轻量模型)
        │
        ├─ 低风险 → 无干预
        ├─ 中风险 → 触发二次验证 (滑块/OTP/不可见挑战)
        └─ 高风险 → 直接拦截 / 标记会话
```

---

## 二、前端采集与检测手段（被动检测，不打断用户）

这些信息能在用户无感的情况下获取，作为实时判断的基础。

### 1. 设备与环境指纹一致性
检测浏览器环境是否被篡改或运行在自动化框架中。

| 检测项 | 正常人类 | 自动化/AI 代理特征 |
|--------|----------|---------------------|
| `navigator.webdriver` | `false` / undefined | `true` (Selenium/Puppeteer/Playwright 默认暴露) |
| `navigator.plugins` / `mimeTypes` | 包含常见插件 | 为空或数量异常 |
| Chrome `runtime` 对象 | 存在 | 无头模式下可能缺失 |
| `window.outerWidth/Height` 与 `screen` 差异 | 合理差值（有浏览器UI） | 差值异常（如无头模式长宽一致） |
| WebGL 指纹 (vendor, renderer) | 正常的GPU厂商 | 虚拟机/无GPU环境常为 "Google SwiftShader" 等软件渲染器 |
| `navigator.hardwareConcurrency` | 常见4-16 | 某些环境会返回固定值或异常值 |
| 浏览器 HAIR (HTML5 API 综合指纹) | 稳定且正常 | 与声称的UA不符，例如声称Chrome却有Firefox的API |

**实时做法：** 页面初始化时立即收集这些信息，打包成指纹哈希，和后端已知正常模式比较。

### 2. 鼠标/触摸轨迹分析（最强生物特征之一）
人类输入带有神经肌肉噪声，而脚本和AI代理即便模拟，也会在微观层面留下痕迹。

**采集颗粒度：** 监听 `mousemove`、`mousedown`、`mouseup`、`touchmove` 等，记录时间戳、坐标、压力（如有）。

**判断指标（可实时计算单个事件或滑动窗口）：**
- **速度与加速度分布**：人类移动有加速-减速曲线，脚本常匀速或线性变化。计算两点间的瞬时速度，统计标准差，太小的标准差可疑。
- **曲率平滑度**：真实鼠标轨迹的曲率变化连续；程序模拟可能由直线段或贝塞尔曲线拼接，导数不连续。
- **微动噪声**：即使人想走直线，也存在高频率小幅度抖动（手抖），频谱分析在高频有能量；AI 生成的路径高频分量往往不足。
- **时间戳间隔**：真实鼠标事件的时间戳间隔不是严格均匀的；自动化工具触发的间隔可能非常整齐（如每 16ms 触发，或由 `requestAnimationFrame` 驱动导致间歇性固定间隔）。
- **悬浮与徘徊**：到达目标前，人类通常有短暂停顿或在目标附近的小范围调整；直接精确命中中心点的轨迹高度可疑。

**实时示例（前端采集片段）：**
```javascript
const trail = [];
window.addEventListener('mousemove', (e) => {
  trail.push({ x: e.clientX, y: e.clientY, t: performance.now() });
  if (trail.length > 50) trail.shift(); // 保持窗口
});
// 每次点击或定期（如每100ms）用 WebSocket 发送最近轨迹片段供后端分析
```

### 3. 键盘行为
- **按键间隔 (Inter-key Delay)**：真实打字时长、停顿、错误敲击（退格键）呈现非固定模式。脚本输入速度极为均匀，或极快（毫秒级内连续输入）。
- **组合键与修饰键**：人类使用Shift、Ctrl 等会有先后时序差异；脚本注入文本不会触发这些。
- **输入法痕迹**：中文等输入法会产生 compositionupdate 事件，直接粘贴或 AI 文本注入会绕过。

### 4. 滚动与页面交互节奏
- **滚动加速度**：鼠标滚轮、触摸板滚动呈现惯性。自动化工具常以固定步长滚动，或者瞬间跳转。
- **阅读停留时间**：人类会随着内容复杂度改变停留时长，AI 代理如果基于 DOM 解析可能瞬间完成，如果基于截图则可能固定间隔扫描。统计页面各区域曝光时间是否过于机械。

### 5. 传感器与硬件 API（移动端尤其有效）
移动设备可以采集：
- **加速计 & 陀螺仪**：真人手持设备存在微动，模拟器通常返回全0或恒定值。
- **触摸面积与压力**：人类手指接触面积和力度动态变化；脚本注入的触摸事件无压力或恒定。

## 三、不可见挑战与陷阱（主动对抗）

当被动检测风险分升高时，可无感注入测试，AI 代理往往会上当。

- **蜜罐表单域**：在隐藏的 `input` 中检测是否被自动填写（人看不到，AI基于DOM填充可能填入）。
- **伪目标检测**：添加透明或位置偏移的不可见按钮，脚本可能盲目点击，人不会。
- **计算难题 (Proof of Work)**：为会话加点计算任务，检测客户端执行时间是否符合正常浏览器性能，并发环境或被篡改的引擎可能异常快或慢。
- **无头浏览器 Canvas 指纹挑战**：渲染特定图形并哈希，不同渲染引擎差异可识别无头 Chrome。

## 四、服务端实时评分与决策

前端数据必须实时回传并分析，架构建议：

1. **特征抽取**：从流式事件中提取窗口特征（如过去5秒的鼠标速度均值、方差、距离、角速度）。
2. **规则引擎 + 机器学习模型**：
   - 规则：`webdriver == true` 直接分+80；5秒内鼠标速度方差 < 阈值 → +50。
   - 轻量级 ML：用孤立森林或 LSTM 自编码器对行为序列建模，输出异常分数。模型可预先用真人与脚本数据集训练。
3. **风险评分融合**：多维度分数加权求和，超过阈值则触发行动。
4. **触发动作**：
   - 低风险 (<30)：放行。
   - 中风险 (30-70)：静默注入验证码或要求滑动验证，收集进一步行为。
   - 高风险 (>70)：拦截请求、标记账户、要求强身份验证。

## 五、针对 AI 代理的特别策略

近两年基于大模型的浏览器代理（如 WebVoyager、Agent-E、各类 Computer Use 代理）会操作真实浏览器，绕过了简单的 `webdriver` 检测和单调轨迹。它们的行为特点：
- **基于截图 + 坐标点击**：鼠标移动可能也是 AI 生成的轨迹，会带有一定的随机性，但往往缺少高频震颤。
- **操作间隔稳定**：每次动作间有固定的“思考延迟”（如3-5秒），之后精确操作。
- **路径简洁**：AI 倾向寻找最短路径，缺乏人类犹豫。
- **异常的事件顺序**：比如在未移动鼠标的情况下直接出现点击，或者频繁使用 Tab 键切换（部分代理的备选方案）。

**应对：**
- **引入不可预测的动态挑战**：如要求拖拽滑块到指定位置，并分析拖拽过程中的速度曲线。
- **行为序列模型**：不仅看单次操作，分析整个会话的操作转换图（页面跳转、操作间隔、操作类型序列），与人类正常流程对比。
- **设备身份与行为关联**：同一设备上多个会话行为高度一致但指纹不同，可能是 AI 集群。

## 六、隐私与合规提示

实时行为监控必须遵守 GDPR、CCPA 等法规：
- 明确告知用户你收集交互数据用于安全目的。
- 尽量避免录制完整屏幕或完整输入内容，只收集行为元数据（坐标、时间、压力等级），并对数据进行脱敏。
- 数据保留期限最小化，实时决策后应尽快匿名化或删除原始事件。

## 七、落地建议步骤

1. **集成设备指纹库**（如 FingerprintJS 开源版或商业化方案），先拿下基础环境异常检测。
2. **部署行为采集 SDK**，只收集鼠标/触摸轨迹和关键点击事件，设置 10-20KB/s 的数据预算，避免拖垮性能。
3. **搭建实时管道**：WebSocket → 后端服务 → Kafka → Flink 作业，输出风险评分，并写入会话上下文。
4. **建立基线**：先让模型在自有数据上无监督训练一周，标记出极端异常点，再人工审核打标，逐步接入拦截。
5. **A/B 测试拦截逻辑**，逐步从“仅记录”到“验证码挑战”再到“硬拦截”，防止误杀。

如果需要更具体的某个模块（比如鼠标轨迹分析算法、Flink 作业示例、模型训练数据格式），可以进一步展开。
